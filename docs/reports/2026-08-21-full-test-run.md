# botty — full test run, 2026-08-21

Complete pass over the application looking for bugs and for what separates it from a
*genuine* assistant. Everything below was either executed against isolated instances or
verified by re-reading the code path end to end (file:line given); nothing was run against the
live 4820/4821 processes. Fixes were **not** applied — this is a findings report; the one
thing built is the `npm run e2e` regression net the backlog asked for.

## 1. Verdict in one paragraph

The core loop works and is well-engineered: funnel → tasks → candidates → nine rules gates →
judgment → nudge behaved exactly as specified under both the deterministic mock and a real LLM
(sensible Spanish extraction, owner inversion, cross-source dedup, one auto-close from thread
evidence, two well-scored nudges, a natural-language "recordame en 2 minutos" delivered 3 s
late). All 745 unit tests and the typecheck are green; the web UI renders seven pages with zero
console errors; TUI and CLI behave. What keeps it from being a trustworthy daily driver is a
cluster of **time/timezone correctness bugs** (the product reasons about "today/tomorrow/EOD"
and renders due dates one day off for a UTC-3 user), a few **state-machine holes** in the
proactive loop (snoozed tasks never come back; meeting-prep tasks never die; clicking "done"
on a nudge is recorded as ignoring it), **unbounded real-mode ingest** (Gmail silently drops
messages past 30 per poll), one **local-origin command-execution** hole, and the absence of
any way to *see or undo* what the assistant did (nudges vanish on reload, reminders can't be
listed or cancelled, dismissed tasks are unreachable).

## 5. What would make it a genuine assistant (prioritized)

1. **One clock.** Every prompt (extraction, judgment, briefing, commitments, meeting-prep) and every client formatter gets the user's local time with offset and weekday; date-only due dates mean end of local day; canonicalize all stored instants to `Z`. Fixes H1/H2 and the SQL-compare family in one sweep.
2. **Closed loops on state.** Snooze expiry re-candidates (`SNOOZE_EXPIRED`); meeting-prep tasks auto-cancel after start/cancel; nudge buttons record the response; dismissed tasks reachable (undo); a "nag" in the same thread bumps the existing task instead of forking; dedup merges requester/due/priority into the survivor.
3. **Memory of what botty did.** `GET /api/notifications` (hydrate nudges/briefings/reminders/auto-closes on reload, both clients), a "today" digest, and chat tools to list/cancel/reschedule reminders and see pending approvals.
4. **Edit, not just capture.** REST + chat tool to edit a task's description/due/requester/owner; snooze/mute with chosen horizons (API already supports it).
5. **Real-mode hardening before daily use.** Gmail paging/`since` from the oldest fetched, automated-sender filtering, outbound/self detection, calendar cancel + per-instance recurrence, jira/github reopen, retention job, process-level error handlers, reminders that say "(was due Fri 18:07)" and expire instead of firing days late.
6. **Trust boundaries.** Restrict Origin to the agent's own port (+ dev origin) or a per-install token; `X-Frame-Options`; wrap open tasks/team notes/tool results in the untrusted markers; consider consent-gating bulk/destructive `task_action`.
7. **Prompt budget legibility.** Reserve space for Tools/constraints; never clip inside a task line; order tasks by priority/due with "+N more"; surface the per-section byte breakdown (already on the backlog).
8. **Judgment economy.** Sticky skip (per-task last-judged cooldown unless the reason changes); cooldown waiver when a task becomes due within the window; distinguish "expired unanswered" from "dismissed" in the prompt (banners have no buttons, so today most nudges count as ignored).
9. **Spanish parity** in the heuristics (funnel + commitment gate) — the owner's traffic is bilingual and the English-only regexes drop Tier-1 signals before any LLM sees them.
10. **Costs you can believe**: record cache tokens / `total_cost_usd`; local-day windows; validate `llm.models` values.
